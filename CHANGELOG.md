## [2.0.0-rc.20261027.1] — 2026-10-27

### Added
- Persisted per-segment Bloom configuration for row and columnar time-series stores. Numeric sizing and disable settings reach physical flush/compaction output; custom factories use an explicit state codec for reopening without rebuilding. Decoder-only configuration can read old custom segments while new writes use built-in or disabled filters.
- `ExchangeCode.MISX` identifies Moscow Exchange at new ordinal 11. Existing ordinals remain unchanged.
- **`DividendHistoryRequest` — an end-to-end cash-dividend fetch path.** A new typed request returning `DividendPayment` records (ex-date, amount, currency, `DividendType`) for one or more symbols over a date range, dispatched through `IDataPipeline.ExecuteAsync<DividendHistoryRequest, DividendPayment>` like every other typed request. The kernel already shipped the storage-side dividend scaffolding — the record, its dataset key, a normalizer, a registered row store, and an L2 write-through — but nothing populated it: no request type reached the fetch path and no adapter extracted dividend cash from any provider, so a consumer could not read per-symbol distributions through the pipeline at all. The request reuses `PriceHistoryRequest`'s batch partitioning and range-narrowing shape (defensive-copied `Symbols`, `init` `Exchange` venue hint, `PartitionKeys`, and `WithRange`), but uses a dividend-specific collision-safe symbol-list encoding in its `DatasetKey`; the optional exchange suffix convention is shared. The batch splitter and time-series gap-fill path therefore serve dividends with no special-casing while collision-prone symbol lists remain distinct. Distributions are an event series rather than a sampled one, so the request takes no frequency parameter and a full year's window typically returns four records rather than one per trading day.
- **A symbol with no ex-dates in the requested window now returns an empty success.** `AddMarketDataKernel` registers a `DividendPayment`-specific response evaluator: when an adapter reaches the provider, parses the window, and finds no distributions, the empty payload is accepted rather than rejected. Previously the pipeline's default evaluator tested the empty payload before it examined coverage, so the ordinary non-paying-symbol case surfaced as `Missing` coverage plus an error-severity `PARTITION_FAILED` issue — indistinguishable from a provider outage, and the common case for any consumer computing income yield across a universe. Genuinely failed fetches still surface as `PARTITION_FAILED`, so the two remain distinguishable.
- **`DividendPaymentDatasetKeyBuilder`** — dataset-key building for `DividendPayment` under the opt-in time-series row-store tier, registered in `AddMarketDataKernel` alongside the sibling builders and entered in the dataset-key builder catalogue that the time-series executor uses to discover a request's key type. Projects a single-symbol partition to `(provider, ticker)`, mirroring the price-bar builder's post-split contract. Without the catalogue entry the registration alone is inert: the time-series path silently wrote no rows.
- **Tiingo dividend adapter.** The companion `Boutquin.MarketData.Adapter` package gains `TiingoDividendHistoryAdapter`, which serves `DividendHistoryRequest` from the **same** daily-price endpoint the price-bar adapter already calls — the per-bar `divCash` field was previously parsed away and discarded, so no new provider endpoint or API quota is involved. It emits one canonical `DividendPayment` per unique ex-date carrying a positive `divCash` and none for zero or negative values; identical duplicate provider rows collapse to that single payment, while conflicting amounts for one ex-date fail the fetch. The adapter persists the raw payload and bases coverage on ex-dates found rather than trading days so the expected non-payment days raise no spurious gap issues. Amounts are stamped `DividendType.Unclassified` with the inference logged: `divCash` is a per-date aggregate that for an ETF routinely blends ordinary income, return of capital, and capital-gain components, so stamping a jurisdictional category would assert an income classification that is wrong for part of the blend.
- **[`docs/dividends.md`](docs/dividends.md)** — the consumer contract for the dividend path: the ownership boundary (the kernel returns `DividendPayment` records; the consumer derives the trailing yield, and no yield calculator belongs in this kernel), a worked trailing-12-month example including the half-open window bound, the host-side normalizer registration a default host needs, the exact-range cache-key rule for pairing a dividend fetch with its covering price fetch, and the empty-window behavior above.
- **Opt-in default normalizer registration.** `AddMarketDataKernel` can now register all nine shipped normalizers (`Bar`, `CorporateAction`, `DividendPayment`, `FactorObservation`, `FuturesSettlement`, `FxRate`, `OptionQuote`, `ScalarObservation`, `YieldCurveQuote`) in one call, behind a new flag `DataPipelineOptions.RegisterDefaultNormalizers` (default `false` — existing consumers see no behavior change until they opt in). Previously nothing registered a normalizer in any production composition, so the pipeline's normalization step silently ran as a no-op; with the flag on, prices round, negative amounts/volumes clamp to zero, and unit strings canonicalize exactly as each normalizer documents. A normalizer a host registers itself — before or after `AddMarketDataKernel` — always wins over the kernel default; `services.RemoveAll<INormalizer<TRecord, TRecord>>()` opts a single record type back out. `InstrumentMetadata` has no shipped normalizer and resolves `null` regardless of the flag. The flag is read when a normalizer is **resolved**, not when `AddMarketDataKernel` runs, so it may be supplied through any options channel in any order — `configurePipeline`, a `Configure` or `PostConfigure` before or after the kernel call, `ConfigureOptions<T>()`, or `IConfiguration` section binding — and `IOptions<DataPipelineOptions>` never reports a value the container contradicts. Resolve normalizers with `GetService`, not `GetRequiredService`: with the flag off the registration resolves to `null` by design. The `Boutquin.MarketData.DependencyInjection` package now references `Boutquin.MarketData.Normalization` **directly** — it already carried Normalization transitively (via its existing reference to `Boutquin.MarketData.Orchestration`), so this is a new direct edge on an already-present dependency, not a new addition to the package's dependency closure; consumers with a lockfile (`packages.lock.json`) should still regenerate it on upgrade. See [`docs/normalization.md`](docs/normalization.md) for what each normalizer does, override/opt-out recipes, and a cache-coherence note for hosts with an already-populated cache directory.
- **Columnar time-series store as an opt-in cache tier.** `DataPipeline.ExecuteAsync` can now route cache reads and gap-fill writes through a per-record-type LSM time-series store instead of the legacy L2 exact-key snapshot store, behind a new preview flag `DataPipelineOptions.UseTimeSeriesStore` (default `false` — existing consumers see no behavior change until they opt in). With the flag on, a request whose date range is already covered by the store returns without any adapter dispatch; only the genuinely missing dates trigger a fetch, and fetched records are appended and deduplicated automatically. See [`docs/time-series-cache.md`](docs/time-series-cache.md) for the full flow.
- **`IDataSnapshot` — point-in-time consistent reads.** `IDataPipeline.AcquireReadSnapshotAsync` returns a disposable handle that serves every read at a fixed point-in-time watermark, so a long-running backtest or curve recalibration sees a coherent view unaffected by concurrent adapter-driven appends. A gap encountered inside a snapshot fails fast (`SnapshotGapException`) rather than dispatching an adapter, preserving the snapshot's stability guarantee.
- **Active columnar quarantine policies.** `DataPipelineOptions.QuarantineBehavior` controls authenticated row-group reads: `FailQuery` throws, `SkipRowGroup` omits corrupted rows, and `TreatAsGap` re-fetches within the current request's dates with partial provenance and a quarantine issue. Failed recovery remains retryable. `DataQualityIncidentSink` receives incidents unless an explicit DI sink overrides it; a logger is the fallback. See [the policy details](docs/time-series-cache.md#quarantine-and-data-quality-incidents).
- **Pluggable compaction strategy and group-commit WAL** for time-series store engines, configurable via `DataPipelineOptions` and the DI store builder. Storage supplies row-segment Bloom filters automatically; custom sizing and persisted factories are supported through the settings and codecs documented in `docs/time-series-cache.md`. The library default (`SizeTiered` compaction, group-commit batching, per-segment bloom filter) is tuned for MarketData's append-mostly workload; `Leveled` and `Full` compaction, custom write-ahead-log tuning, and a per-record row-format opt-out are available for consumers with different access patterns.
- **`ImportLegacyL2SnapshotsCommand`** — a warm-start importer that back-fills the new time-series store from an existing L2 snapshot store, so adopters enabling `UseTimeSeriesStore` on a populated deployment do not start from an empty cache. Idempotent on re-run.

The L2 snapshot store (`ISnapshotStore`) remains the active default path and continues to receive full support with `UseTimeSeriesStore = false`.

### Changed — BREAKING
- `ExchangeCode` enum members renamed to match ISO 10383 MIC assignments. The enum previously labelled `XTSE` as *Tokyo* and `XTOR` as *Toronto*, which inverted the ISO standard (`XTSE` is Toronto; Tokyo is `XTKS` under Japan Exchange Group's `XJPX` operating MIC). Concretely: `ExchangeCode.XTSE` → now means Toronto Stock Exchange (was Tokyo); `ExchangeCode.XTOR` → **removed**; `ExchangeCode.XTKS` → **new** member at the same numeric ordinal that `XTSE` previously occupied (slot 2), represents Tokyo. Numeric ordinals are pinned: slot 2 is Tokyo, slot 9 is Toronto, both unchanged. Consequences:
  - Integer-serialized data is **unaffected** — a cached value of `9` continues to identify Toronto; a cached value of `2` continues to identify Tokyo.
  - String-serialized data (JSON `"XTSE"` / `"XTOR"`) is affected. Downstream consumers that persist or transport the enum as a string name must migrate: literal `"XTSE"` now means Toronto (was Tokyo); literal `"XTOR"` is no longer a recognized member.
  - `ExchangeMetadata.GetTimeZone(ExchangeCode.XTSE)` now returns `TimeZoneCode.EST` (was `JST`); `GetCountry(XTSE)` returns `CountryCode.CA` (was `JP`). Callers that branched on these return values should re-audit.
  - No ETFWealthIQ portfolio or benchmark referenced Tokyo-listed instruments at the time of the rename (the only occurrences of `"XTSE"` in the codebase were the enum member itself and one metadata test, both moved to `XTKS`), so no persisted portfolio data required migration.
- The `CurrencyCode` enum is **removed**; every currency-typed member is now `Boutquin.Domain.Currency`. The kernel previously defined a 14-member `ReferenceData.CurrencyCode` enum; the ecosystem now speaks a single ISO 4217 enum, the full 177-member `Boutquin.Domain.Currency` (with an `Unspecified = 0` sentinel). Affected surfaces: `FxRateDatasetKey.BaseCurrency`/`QuoteCurrency`, `DividendPayment.Currency`, `CorporateAction.Currency`, `FxPair.BaseCurrency`/`QuoteCurrency`, `RateBenchmark.Currency`, `StandardBenchmarks`, and `IDividendClassifier.Classify`. Consequences:
  - Integer- and columnar-serialized data is **unaffected**. Both enums use identical ISO 4217 numeric backing (`USD = 840`, `EUR = 978`, `GBP = 826`, `CAD = 124`, `CHF = 756`, `JPY = 392`, …) and the former 14 members are a same-name, same-value subset of `Currency`, so every persisted currency column — including the `FxRateDatasetKey` partition-key columns and the `DividendPayment` row column — round-trips byte-identically and key ordering is preserved.
  - Source-level consumers recompile against `Boutquin.Domain.Currency` (members are accessed unchanged, e.g. `Currency.USD`). The package now requires `Boutquin.Domain` ≥ `0.7.1`.
  - `default(Currency)` is the new `Currency.Unspecified` (numeric `0`) sentinel, which `CurrencyCode` had no equivalent for. An uninitialised currency now surfaces as the explicit `Unspecified` value rather than defaulting to the first declared member.

### Changed
- **`Boutquin.Storage` dependency bumped to the 2.0 line.** The time-series store cache tier (above) consumes Boutquin.Storage 2.0's tagged-wire serialization and columnar segment format. Boutquin.Storage 2.0 is a breaking wire-format change from 1.x — any preview-flag adopter who had already populated a time-series store directory under a pre-2.0 build **must delete the stored segments and re-ingest** before upgrading and toggling `UseTimeSeriesStore` on. See [`docs/time-series-cache.md`](docs/time-series-cache.md#storage-format-versioning) for the operational detail and the fail-fast behavior if the delete-and-re-ingest step is skipped.
- `FactorObservation` is reshaped from a dictionary payload to one record per `(Date, FactorName, Value)`. The old `IReadOnlyDictionary<string, decimal> Factors` member is replaced by a `string FactorName` and a `decimal Value`, so the record is now columnar-native: the `FactorName` column dictionary-encodes and runs of the same factor compress, where the dictionary payload previously forced a row-format fallback. A multi-factor observation date (a Fama-French CSV row listing Mkt-RF, SMB, HML, …) now produces one `FactorObservation` per factor, all sharing the same `Date`; consumers group by `Date` to recover the row-wise view of every factor on a date. The per-factor canonicalisation rules in `FactorObservationNormalizer` are unchanged (canonical casing for Mkt-RF, SMB, HML, RMW, CMA, RF, Mom, WML; unknown names trimmed and uppercased; percent-to-decimal value conversion) — they now apply to the single `FactorName`/`Value` pair. The factor-series dataset key is unaffected: it remains the series identity `(Provider, DatasetId, Frequency)`, since the factor name is now a column rather than part of the partition key.
- `YieldCurveQuote` is now a dated, columnar-native record. It gains a `DateOnly Date` first positional parameter — the curve's as-of date — and implements the time-series date contract (`IHasDate`), matching the convention of every other dated canonical record (`Bar`, `FxRate`, `ScalarObservation`, …). The record is annotated `[ColumnarStorable]` and declared `partial`, so it participates in the columnar on-disk segment format with the generator-default codecs (`Date` → delta-of-delta, `Tenor`/`Rate` → dictionary). A full curve snapshot is now the set of `YieldCurveQuote` records sharing one `Date`; consumers group by `Date` to reconstruct a single curve. `YieldCurveQuoteNormalizer` preserves `Date` unchanged through normalization while keeping its existing tenor-uppercasing and percent-to-decimal rate semantics.
- `FallbackOrchestrator.ExecuteAsync` now calls each adapter's `CanHandle(request)` and skips adapters that return `false`, recording the skip in the attempts list. Previously the orchestrator fetched from every prioritized adapter in turn and trusted the evaluator to reject bad responses — but adapters already express their preconditions in `CanHandle` (frequency, batch size, and now venue support via the 1.1.0 `Exchange` hint), so skipping early is both more honest and more efficient. Unlocks the per-venue adapter routing introduced in `Boutquin.MarketData.Adapter` 1.1.0: TSX-listed requests now bypass Tiingo (which would otherwise happily return an unrelated US equity sharing the ticker) and go directly to TwelveData.

### Added
- `ExchangeCode? Exchange` parameter on all eight data-request records — `PriceHistoryRequest`, `InstrumentMetadataRequest`, `FxHistoryRequest`, `EconomicSeriesRequest`, `FactorSeriesRequest`, `FuturesSettlementRequest`, `OvernightFixingRequest`, and `YieldCurveQuoteRequest`. Defaults to `null` for full back-compat: existing consumers that do not set `Exchange` produce exactly the same `DatasetKey` as before, so existing L2 snapshots remain reachable without migration. When non-null the exchange code is appended to `DatasetKey` via `/` (e.g. `AAPL` → `AAPL/XNAS`, `DGS10` → `DGS10/XNYS`), naturally partitioning the L2 cache into a sub-directory per venue and letting adapter-selection orchestrators filter to sources that cover the specified exchange. This is the kernel-side prerequisite for routing bare CA tickers like `XIC` to TSX-native adapters rather than to Tiingo (which happily returns an unrelated US equity for the same symbol), and for picking the right trading calendar at the pipeline layer.

### Fixed
- Corrected `XMOS` to the ISO registry's clearing-organization identity and `NEOE` to Cboe Canada NEO-L. Consumers that used `XMOS` intending Moscow Exchange must explicitly migrate those records to `MISX`; existing values are not silently rewritten.
- Corrected ICMA documentation to distinguish the schedule-free ACT/365.25 approximation from coupon-aware calculation, with all six primary published examples and independent Gregorian Easter vectors in regression coverage.
- **Qualified Storage 2.0 integration.** Generated wire layouts and store configuration now match the qualified dependency API. File stores can read the earlier literal-path snapshot/raw-document layouts while new writes use the current encoded layout; raw documents reject invalid Unicode instead of silently replacing data.
- **Cache and snapshot ownership.** Expired L1 entries are reclaimed during subsequent cache activity, mutable inputs no longer leak through snapshot/catalog wrappers, and store registrations dispose their owned resources once.
- **Coverage and calendar accuracy.** Overlapping stale-tail refreshes are merged before dispatch. Coverage calculations bound ratios and preserve sparse-event completion. Calendar metadata includes the January 2025 NYSE closure, corrected SIFMA dates, and a separate SOFR publication calendar with documented Fed exceptions; SONIA publication lag is one London business day.
- HTTP attempt deadlines now cover response-body buffering without changing borrowed-client timeouts; each retry consumes a rate-limit permit. Negative response caps are rejected, mapped IPv4 private literals are checked, and URI user-info is removed from debug logs. Kernel-created HTTP clients no longer follow redirects automatically; injected clients must disable redirects themselves. Private-network option documentation now explicitly describes its literal/known-host scope and DNS limitation.
- Corrected TSX Victoria Day and Saturday Christmas observation, NYSE Juneteenth adoption (2022), and TARGET fixed-date holidays without substitute weekdays. Composite calendars now copy their constituent array so caller array replacement cannot change an existing calendar.
- Multi-row time-series recovery persists and reloads known-empty spans per factor, tenor, or contract key. A rebuilt host can replay those spans offline; partial source responses cannot certify missing rows as empty.
- Time-series single-row recovery persists selected providers and complete attempted ranges through the checkpoint store. Restart and bounded-index eviction retain cache recovery; fallback providers' physical series merge deterministically instead of losing an earlier prefix. Partial provider responses remain eligible for retry.
- Both execution paths honor the registered request partitioner and continue/stop failure policy. Legacy snapshot ingestion safely restarts from partition zero because intermediate payloads are not durably checkpointed; its checkpoint identity includes typed request, full dataset key, range, and frequency, and advancement never skips an unsuccessful prefix.
- Kernel DI keeps keyed registrations intact during decoration, requires separate record-type store roots, replaces per-record store overrides, and reports null service collections at the public entry point. Public partition issues no longer copy raw adapter exception text.
- Normalizers consistently reject null string members. Futures implied-rate fallback applies only to supported rate products and uses decimal rates, aligned with the companion CME adapter. Packaged XML documentation is checked for private planning references in CI.
- Public API snapshots now match the compiled surface across all packages, including generated members. Builds enforce both missing declarations (`RS0016`) and stale declarations (`RS0017`); historical removed signatures remain recorded without changing runtime APIs.
- **Multi-row-per-date record types now fan out to one series per row under the time-series store tier.** `YieldCurveQuote` (by `Tenor`), `FactorObservation` (by `FactorName`), and `OptionQuote` (by `Expiry`/`Strike`/`Type`, via a non-persisted keyed-row fetch envelope pairing contract identity with the quote body) now fan out on the gap-fill append path into one `DatasetKey` per discriminant, and merge back across all of them on read — so a co-dated N-row set (a full yield curve, a full factor set, a full option chain) round-trips as N rows instead of collapsing to a single last-writer-wins row. Coverage/gap detection and idempotency are per-discriminant-key. See the "Per-row-discriminant fan-out for multi-row-per-date record types" section of [`docs/time-series-cache.md`](docs/time-series-cache.md) for the full behavior. Behind the existing preview flag `DataPipelineOptions.UseTimeSeriesStore` (default `false`), so no shipped consumer is impacted.
- **`DataPipelineOptions.TimeSeriesStalenessMaxAge` now takes effect on the per-row-discriminant fan-out path.** Fan-out records (`YieldCurveQuote`, `FactorObservation`, `OptionQuote`) live only under fully-populated per-discriminant keys, never under the blanked-discriminant key the staleness check probed — so the newest-record probe always came back empty and the configured max-age was silently inert for every fan-out record type: a fully date-covered but wall-clock-stale curve/factor-set/option-chain was never re-fetched. The staleness rule now reuses the newest as-of date the per-discriminant cross-key scan already discovers (the freshest observation across all of the entity's discriminant series) and re-fetches the stale tail across the whole entity when it exceeds the window. Double-gated behind `UseTimeSeriesStore` (default `false`) **and** `TimeSeriesStalenessMaxAge` (default `null`), so no shipped consumer is impacted.
- **The per-row-discriminant fan-out path now clamps already-attempted-and-empty spans per discriminant, so a permanently source-absent contract stops re-dispatching the adapter forever.** The single-key gap-fill path records the span it dispatched an adapter for and subtracts it from future gaps (a leading pre-inception hole subsumes to a cache hit instead of re-fetching). The fan-out path bypassed that clamp entirely — correct for the coarse, tenor-blind per-request index, but it recorded *no* per-discriminant attempt, so a discriminant that is historically known (≥1 stored row) yet permanently absent at the source over part of the range — a rolled-off/expired option contract, a discontinued futures month — had its permanent hole re-added to the gap union on every read and re-dispatched the adapter indefinitely; it never subsumed to a cache hit. The fan-out path now tracks attempted ranges per fully-populated discriminant key (mirroring the single-key `IAttemptedRangeIndex`/`RecordAttempt`/`ClampAttemptedSpans` mechanism) and clamps each known key's gaps by its own attempts, so such a hole is dispatched at most once and then subsumes. Idempotency and per-discriminant gap detection are unchanged. Behind `UseTimeSeriesStore` (default `false`), so no shipped consumer is impacted.
- **The per-row-discriminant fan-out key no longer depends on whether normalization ran, and a store written under the older key encoding now fails fast instead of silently forking.** `FactorName` and `Tenor` are simultaneously record body columns and fan-out dataset-key discriminants, and the shipped normalizers rewrite those columns — so with `RegisterDefaultNormalizers` flipped on over a populated store, one logical factor or tenor split into a raw-era key and a normalized-era key. Both sat inside the `(prefix, *)` scan and both satisfied the discriminant-blind membership filter, so reads merged two parallel series permanently (the raw-era key is never re-fetched). The discriminant is now canonicalised by the key type itself (`FactorObservationDatasetKey.CanonicalFactorName`, `YieldCurveQuoteDatasetKey.CanonicalTenor`) on **every** append, whether or not a normalizer is registered, and the normalizers apply the same functions to the body — so the persisted key is invariant under normalization. **This is an on-disk key-encoding change** for any series whose discriminant was not already canonical: the shipped tenor sources publish canonical labels and are unaffected, but a factor archive whose CSV headers are non-canonical (`"ST_Rev"`, `"Lo 10"`) was previously keyed under the raw spelling. A fan-out read that reaches such a key now raises `MarketDataStorageException` naming both spellings and the remedy, rather than re-keying silently and double-counting every shared date; delete the stored segments for that record type and re-ingest. See [`docs/time-series-cache.md`](docs/time-series-cache.md#migrating-a-store-written-before-the-canonicalisation). Behind `UseTimeSeriesStore` (default `false`), so no shipped consumer is impacted.
- `Symbol` is now annotated with `[JsonConstructor]` on its parameterized constructor so `System.Text.Json` round-trips through `JsonSnapshotSerializer<T>` (and any other `camelCase`-policy reader) repopulate `Ticker` instead of falling back to the implicit parameterless struct constructor and leaving the get-only property `null`. Previously, every `InstrumentMetadata` record read back from an L2 snapshot had `Symbol.Ticker == null`, so downstream consumers that keyed by ticker (e.g. `envelope.Payload.ToDictionary(m => m.Symbol.Ticker, ...)`) threw `ArgumentNullException` on the first record and the whole metadata pre-fetch was caught-and-swallowed — research pipelines silently fell back to CSV-only enrichment with no inception dates.
- `InstrumentMetadataRequest.DatasetKey`, `PriceHistoryRequest.DatasetKey`, and `FxHistoryRequest.DatasetKey` now join their symbols/pairs with `_` instead of `+`. The cache key built by `DataPipeline.ExecuteAsync` (format `{TRecord}/{DatasetKey}/{from}/{to}`) flows into `FileSystemObjectStore.ValidateKey`, whose allowed-character set is `[a-zA-Z0-9._\-/]`. A multi-symbol batch (e.g. a 35-ticker CA ETF universe metadata pre-fetch) produced a `+`-laden key that threw `ArgumentException: Key contains invalid characters`, silently disabling the L2 snapshot write-through and — in the downstream consumer's `catch` block — skipping the metadata pre-fetch entirely so consumers fell back to CSV-only enrichment with no inception dates. Switching the join character keeps the key deterministic, order-independent, and compliant with the object-store validator.
- `CoverageComputation.CountBusinessDays` now guards against `DateOnly.MaxValue.AddDays(1)` overflow by breaking the loop when `current == to` before incrementing. Also adds a fast-path that returns 0 immediately when the range spans the full `DateOnly` representable range (`MinValue` to `MaxValue`), which is the sentinel range used by point-in-time requests such as `InstrumentMetadataRequest`. Previously, calling the pipeline for a metadata request when all adapters failed caused an unhandled `ArgumentOutOfRangeException` to propagate to the caller — masking the real failure (all adapters returned empty results) with a cryptic overflow error.

## [1.0.0] — 2026-04-17

First public release. Boutquin.MarketData ships a shared data ingestion kernel for the Boutquin financial-software ecosystem: typed transport, multi-level caching, durable storage, deterministic normalization, business-day calendars, day-count conventions, ISDA instrument conventions, and a full canonical reference-data taxonomy — all with zero dependency on Analytics, Trading, or OptionPricing. Concrete source adapters live in the companion `Boutquin.MarketData.Adapter` repository; the kernel ships contracts and infrastructure only.

### Highlights

- **Full eight-step pipeline with two-level caching.** `DataPipeline.FetchAsync` executes: L1 in-memory cache check → L2 snapshot check → adapter selection → fetch → normalize → L2 write → L1 promote → return. Issue entries (`DataIssue`) persist through L2 round-trips so warnings survive cache hits. L1 cache misses set `RetrievalMode.Cache` on provenance so callers can distinguish cached from fresh data.
- **Typed reference data across two tiers.** Tier 1 covers core market identifiers: `CurrencyCode` (ISO 4217, numeric values stable for persistence), `ExchangeCode` (ISO 10383 MIC), `AssetClassCode`, `SecuritySymbolStandard`, and `Symbol`. Tier 2 adds market-structure taxonomies: `CountryCode` (ISO 3166-1), `ContinentCode`, `TimeZoneCode`, and `DividendType` (eight issuer-declared categories, no sentinel). `ExchangeMetadata` and `CountryMetadata` provide exhaustive static lookup with a compile-error on synthetic casts.
- **Typed provenance and diagnostics.** `DataProvenance` carries `ProviderCode` (case-insensitive via lower-case normalisation), `LicenseType`, and `RetrievalMode`. `DataIssue` carries `IssueCode` (upper-case normalisation, eight well-known statics) and `IssueSeverity`. Mix-ups that previously required string comparison are now compile errors.
- **Typed external identifiers.** Five strongly-typed record structs — `YieldCurveId`, `EconomicSeriesId`, `FactorDatasetId`, `FuturesProductCode`, and `ContractMonth` — eliminate cross-request-type mix-ups at the call site. Assigning a `YieldCurveId` to a `FactorDatasetId` field is a `CS0029` diagnostic, not a silent runtime error.
- **Transport hardened against SSRF, response-size attacks, and credential leaks.** `ResilientHttpDataTransport` validates every URI before dispatch (scheme, loopback, RFC-1918, link-local, CGNAT, and hostname blocklist), enforces a configurable `MaxResponseBytes` cap (default 32 MiB) with streaming abort, and redacts configured query-parameter names in debug logs. Retry is narrowed to genuine transport failures; owned `HttpClient` uses `PooledConnectionLifetime = 2 minutes` for DNS-change resilience.
- **Zero domain dependencies, enforced.** Architecture tests assert that no assembly in the kernel references `Boutquin.Analytics`, `Boutquin.Trading`, or `Boutquin.OptionPricing`, and that concrete `System.IO` types (`File`, `Directory`, `FileStream`, …) are confined to the Storage package. The Coverlet instrumentation class is excluded from all architecture assertions per the documented coverlet/NetArchTest workaround.

### Added

#### Core Contracts (`Boutquin.MarketData.Abstractions`)

- **Canonical records** under `Records/`: `Bar` (OHLCAV price bar), `FxPair` / `FxRate` (currency pair and spot rate), `ScalarObservation` (single-value time series), `YieldCurveQuote` (tenor + rate), `FuturesSettlement` (settlement price with typed `FuturesProductCode` and `ContractMonth`), `InstrumentMetadata` (symbol, exchange, asset class, symbol standard), `DividendPayment` (ex-date, amount, currency, `DividendType`), `CorporateAction`, `OptionQuote`, `FactorObservation`.
- **Typed request models** under `Requests/`: `PriceHistoryRequest`, `FxHistoryRequest`, `EconomicSeriesRequest`, `YieldCurveQuoteRequest`, `InstrumentMetadataRequest`, `OvernightFixingRequest`, `FactorSeriesRequest`, `FuturesSettlementRequest`. All symbol and pair collections are defensively copied at construction so post-construction mutation cannot affect `DatasetKey` stability or record equality.  `DateRange` rejects inverted ranges (`To < From`) at construction.
- **Pipeline contracts**: `IDataRequest`, `IDataSourceAdapter<TRequest, TRecord>`, `IPrioritizedAdapter`, `IFallbackResponseEvaluator<TResponse>`, `IDataPipeline`, `ILocalCache`, `ISnapshotStore`, `INormalizer<TRaw, TCanonical>`, `IFixingsStore`.
- **Tier 1 reference-data enumerations**: `CurrencyCode` (ISO 4217 numeric values — USD=840, EUR=978, …), `ExchangeCode` (ISO 10383 MIC), `AssetClassCode`, `SecuritySymbolStandard`. `Symbol` readonly record struct: null/whitespace-rejecting, `IComparable<Symbol>`, ordinal ticker ordering.
- **Tier 2 market-structure taxonomies**: `CountryCode` (ISO 3166-1 alpha-2, 11 members), `ContinentCode` (UN geoscheme, 7 members), `TimeZoneCode` (ISO 8601, 9 standard-time designators), `DividendType` (8 issuer-declared categories — no `Unknown` sentinel, adapter classification is mandatory). `ExchangeMetadata.GetTimeZone(ExchangeCode)` and `.GetCountry(ExchangeCode)` — exhaustive, thread-safe, throw `ArgumentOutOfRangeException` on synthetic casts. `CountryMetadata.GetContinent(CountryCode)` — same contract. `IDividendClassifier` contract: never throws on well-formed inputs, never returns `default`, broad-fallback rules documented.
- **Typed provenance** under `Provenance/`: `ProviderCode` readonly record struct with lower-case normalisation and `System.Text.Json` round-trip support; `LicenseType` enum (`Free`, `DelayedFifteenMin`, `Commercial`, `ResearchOnly`, `Redistribution`); `RetrievalMode` enum (`Api`, `Cache`, `Snapshot`, `Derived`, `Fixture`).
- **Typed diagnostics** under `Diagnostics/`: `IssueSeverity` enum (`Warning`, `Error`); `IssueCode` readonly record struct with upper-case normalisation and eight well-known statics — `MissingField`, `StaleData`, `RateLimited`, `HolidayGap`, `UnexpectedGap`, `SchemaDrift`, `SnapshotStale`, `PartitionFailed`.
- **Typed external identifiers** under `ReferenceData/`: `YieldCurveId`, `EconomicSeriesId`, `FactorDatasetId`, `FuturesProductCode` (thin `Symbol`-style wrappers, null/whitespace-rejecting, case-preserving); `ContractMonth` (structured `(Year, Month)` with canonical `YYYY-MM` rendering, string constructor accepting both `YYYY-MM` and `YYYYMM`, implicit `DateOnly` conversion to first-of-month for sort ergonomics).
- **Rate benchmarks**: `RateBenchmark`, `BenchmarkKind`, `BenchmarkName`, `StandardBenchmarks` — six pre-built benchmark instances covering SOFR, SONIA, ESTR, CORRA, SARON (CHF), and TONA (JPY) with associated calendar codes and day-count conventions (Hull 11e Ch 4 p.99–100).
- **`ISecurityResolver`** — dual-listing resolver contract with identity-on-miss, reflexive, and commutative invariants for unknown symbols; `AllListings` returns `IReadOnlyCollection<Symbol>`.
- **Exception hierarchy** under `Exceptions/`: abstract `MarketDataException` base plus sealed `MarketDataNotFoundException`, `MarketDataRetrievalException`, `MarketDataProcessingException`, `MarketDataStorageException`, `SymbolNotFoundException`. Every type supports `(string)` and `(string, Exception)` constructors for inner-exception chaining.
- **`DataEnvelope<TRecord>`** wrapping records with `DataProvenance` and a `IReadOnlyList<DataIssue>` collection. `FallbackResult<TResponse>` and `FallbackAttempt` carry `ProviderCode` throughout the fallback chain.
- **`CoverageComputation`** — coverage aggregation using `long` accumulators with a single pass and a `checked` narrowing cast; enforces the canonical `MissingPoints = max(0, requested − returned)` identity.

#### Transport (`Boutquin.MarketData.Transport`)

- **`ResilientHttpDataTransport`** implementing `IHttpDataTransport` and `IAsyncDisposable`: Polly v8 resilience pipeline with retry and exponential backoff; URI validation blocking SSRF vectors (loopback, link-local, RFC-1918, CGNAT, ULA, and hostname blocklist) with opt-in `TransportOptions.AllowPrivateNetworks`; `MaxResponseBytes` cap (default 32 MiB) enforced in both the pre-flight `Content-Length` check and the streaming-copy loop, aborting and disposing the response on cap breach; debug-log redaction of query parameters listed in `TransportOptions.SensitiveQueryParameters` (defaults cover `token`, `apikey`, `api_key`, `apitoken`, `api_token`, `secret`, `access_token`, `auth`); retry predicate narrowed to transport-level failures only; owned `HttpClient` uses `SocketsHttpHandler.PooledConnectionLifetime = 2 minutes`; does not mutate a caller-owned `HttpClient.Timeout`; `IAsyncDisposable` implementation with `Interlocked.Exchange` idempotency guard disposing the owned `SlidingWindowRateLimiter` without blocking on in-flight permits.

#### Cache (`Boutquin.MarketData.Cache`)

- **`ExactOnceMemoryCache`** implementing `ILocalCache`: TTL-based in-memory cache with atomic TOCTOU-narrowed expiry reclaim and type-safe retrieval (returns `default` on type mismatch, never throws `InvalidCastException`).
- **`WriteThroughCache`** — write-through wrapper over `ISnapshotStore` using `await using` on every `ISnapshotStore.ReadAsync` result to prevent blocking disposal on file-backed streams.

#### Storage (`Boutquin.MarketData.Storage`)

- **`FileSnapshotStore`** and **`InMemorySnapshotStore`** implementing `ISnapshotStore` with atomic writes.
- **`SnapshotEnvelopeSerializer`** — 1 MiB upper bound on the metadata JSON length prefix; rejects out-of-range values with `InvalidDataException` before any allocation, preventing negative-length or gigabyte-scale allocation from a corrupted or hostile payload.
- **`IngestionCheckpointStore`** — deserialised checkpoints are rejected when `SymbolIndex < 0`, `Provider` is empty, or `Dataset` is empty; `JsonException` during deserialisation is caught and re-raised with pipeline context.
- **`InMemoryFixingsStore`** implementing `IFixingsStore`: last-in-wins seeding, keyed by `BenchmarkName` + `DateOnly`, returning `decimal?` or `TimeSeriesPoint<decimal>`.
- **`FileRawDocumentStore`** implementing `IRawDocumentStore`: explicit path-traversal defense rejecting `..`/`.` segments, empty segments, absolute-rooted keys, and drive-letter prefixes before delegating to the underlying store; defense documented as an interface-level contract on `IRawDocumentStore.SaveAsync`.

#### Catalog (`Boutquin.MarketData.Catalog`)

- **`SourceRegistry<TRequest, TRecord>`** — provider registration with priority ordering and `ProviderCode`-keyed lookup (case-insensitive); constructor null-checks the adapter collection and each element, re-raising duplicate-key exceptions with the full key list.
- **`DatasetKey`** record-struct rejects null/whitespace values via `ArgumentException.ThrowIfNullOrWhiteSpace`.

#### Calendars (`Boutquin.MarketData.Calendars`)

- **`IBusinessCalendar`** contract with `IsBusinessDay(DateOnly)`, `Advance(DateOnly, int)`, and `CountBusinessDays(DateOnly, DateOnly)`. `BusinessCalendarBase` rejects `int.MinValue` steps with `ArgumentOutOfRangeException` (avoiding `Math.Abs(int.MinValue)` overflow).
- **`HolidayCalendar`** — full holiday-rule calendar with null-checked constructor and immutable holiday set via collection expression.
- **`HolidayCalendarFactory`** backed by an `ImmutableArray<string>` code list: `USNY`, `GBLO`, `TARGET`, `CATO`, `XCME`, `USSF`, `CAST` delivered as full holiday-rule calendars; `ZURH` and `TKYO` served by `WeekendOnlyCalendar` fallback so `StandardBenchmarks.ChfSaron` and `.JpyTona` resolve without an ad-hoc dataset.
- **`CalendarHelpers.ComputeEaster`** — rejects years outside `[1583, 9999]` (Gregorian adoption floor / `DateOnly` upper bound). **`NthDayOfWeek`** rejects `n` outside `[1, 5]`.

#### Day-Count Conventions (`Boutquin.MarketData.DayCount`)

- Five conventions implementing `IDayCountConvention`: `Actual360` (ACT/360), `Actual365Fixed` (ACT/365F), `ActualActualInPeriod` (ICMA Rule 251 — US Treasury / euro government bonds; ICMA ACT/365.25 fallback when no coupon context provided), `Thirty360` (ISDA 2006 §4.16(f) Bond Basis — D2 is capped to 30 only when capped D1 is already 30 and D2 is 31, distinguishing Bond Basis from 30E/360 on spans where D2 = 31 and D1 < 30), `ThirtyE360` (ISDA 2006 §4.16(g) Eurobond — unconditional D1/D2 cap to 30).
- All conventions reject `endDate < startDate` with `ArgumentOutOfRangeException`; negative year fractions almost always indicate a schedule-generation bug.
- **`DayCountResolver`** — trims and case-folds input; resolves aliases `ACT/ACT`, `ACTUAL/ACTUAL`, `ACT/ACT ICMA`, `ACT/ACT BOND`, `30E/360`, `EUROBOND`, `EUROBOND BASIS`.

#### Instrument Conventions (`Boutquin.MarketData.Conventions`)

- **`InstrumentConventionRegistry`** with pre-built `CreateDefault()` producing four-currency OIS, FRA, futures, and swap-leg catalogues.
- Records: `OisConvention`, `FraConvention`, `SwapLegConvention`, `FutureContractConvention`, `SettlementConvention`. Supporting enums: `PaymentFrequency`, `RollConvention`, `StubConvention`, `ObservationShiftConvention`. Interface `IInstrumentConvention`. No dependency on `Boutquin.Curves` — architecture tests enforce isolation.

#### Normalization (`Boutquin.MarketData.Normalization`)

- Nine normalizers implementing `INormalizer<TRaw, TCanonical>`: `BarNormalizer`, `FxRateNormalizer`, `ScalarObservationNormalizer` (with public `const CanonicalDecimalUnits` for caller reference), `YieldCurveQuoteNormalizer`, `FuturesSettlementNormalizer`, `DividendPaymentNormalizer`, `CorporateActionNormalizer`, `OptionQuoteNormalizer`, `FactorObservationNormalizer`. Reference-type inputs reject null; record structs do not require a null guard. Instrument metadata supports write-through storage without a normalizer.

#### Orchestration (`Boutquin.MarketData.Orchestration`)

- **`DataPipeline`** implementing `IDataPipeline`: eight-step orchestration (validate → L1 check → L2 check → adapter select → fetch with fallback → normalize → L2 write → L1 promote). When `ContinueOnPartitionFailure = false` and a partition fails, the L2 write and L1 promotion are skipped — a partial batch is not cached as authoritative. **`CoverageResponseEvaluator`** null-guards the response before dereferencing `Payload` and accepts an optional `MinimumCoverageRatio` constructor parameter for strict-mode pipelines.

#### Dependency Injection (`Boutquin.MarketData.DependencyInjection`)

- **`AddMarketDataKernel`** — idempotent `IServiceCollection` extension registering transport, L1 cache, L2 write-through cache, and pipeline for all ten canonical record types (`Bar`, `FxRate`, `ScalarObservation`, `YieldCurveQuote`, `FuturesSettlement`, `InstrumentMetadata`, `DividendPayment`, `CorporateAction`, `FactorObservation`, `OptionQuote`). **`AddMarketDataWriteThroughFor<TRecord>()`** extension for downstream repos registering custom record types.

#### Testing (`Boutquin.MarketData.Testing`)

- **`EnvelopeBuilder`** — fluent builder for `DataEnvelope<TRecord>` test fixtures accepting typed `ProviderCode`, `LicenseType`, `RetrievalMode`, `IssueCode`, and `IssueSeverity`. Default envelope carries `LicenseType.Free` + `RetrievalMode.Fixture`.
- **`FakeDataSourceAdapter`** — produces a fresh `HttpResponseMessage` per `SendAsync` via a factory closure, eliminating the test-flake pattern caused by a shared-instance content stream being exhausted on second call.
- **`FakeHttpMessageHandler`** — deterministic HTTP message handler for adapter unit tests.
